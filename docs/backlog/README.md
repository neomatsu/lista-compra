# Backlog de mejoras

Este backlog organiza las mejoras propuestas para la app Lista de la compra en sprints incrementales.

## Sprints

1. [Sprint 01 - Catalogo editable](./sprint-01-catalogo-editable.md)
2. [Sprint 02 - Experiencia para personas mayores](./sprint-02-experiencia-personas-mayores.md)
3. [Sprint 03 - Sincronizacion de catalogo familiar](./sprint-03-sincronizacion-catalogo-familiar.md)
4. [Sprint 04 - Calidad PWA y mantenimiento](./sprint-04-calidad-pwa-y-mantenimiento.md)

## Orden recomendado

El orden propuesto busca entregar valor visible pronto y dejar la sincronizacion avanzada para cuando el modelo local este claro:

1. Primero se implementa catalogo editable local.
2. Despues se mejora la experiencia para personas mayores.
3. Luego se sincroniza el catalogo familiar.
4. Por ultimo se refuerzan pruebas, PWA y mantenimiento.

## Criterio de priorizacion

- **P0/P1 funcional**: reduce escritura repetida y hace la app mas util en la compra diaria.
- **P1 accesibilidad**: baja el riesgo de error para usuarios mayores.
- **P1/P2 sincronizacion**: mejora el uso familiar, pero requiere mas cuidado tecnico.
- **P2/P3 mantenimiento**: sostiene futuras mejoras sin acumular fragilidad.
